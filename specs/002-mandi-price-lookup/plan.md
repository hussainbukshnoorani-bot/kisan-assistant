# Implementation Plan: Mandi Price Lookup

**Branch**: `002-mandi-price-lookup` | **Date**: 2026-09-26 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/002-mandi-price-lookup/spec.md`

## Summary

Farmers send a WhatsApp message or SMS in Urdu script or Roman Urdu asking a crop's price at a
mandi; the bot replies on the same channel, in the same script, with the latest valid price
(Rs per 40 kg, min–max), the source name, and the price date — or an honest "not available /
not current" reply, or one clarifying question.

Technical approach: a Python/FastAPI service receives signed webhooks, extracts crop and mandi
with a normalising synonym dictionary (LLM fallback that may only pick dictionary IDs), reads
pre-fetched prices from PostgreSQL, and renders the reply from a reviewed bilingual template
catalogue sized per channel. A scheduled job fetches and validates prices from the Punjab AMIS
source. No price or reply text is ever generated by the LLM.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: FastAPI, Uvicorn, Pydantic v2, SQLAlchemy 2.0, Alembic, httpx,
selectolax (HTML parsing), rapidfuzz, anthropic SDK (`claude-haiku-4-5`), structlog,
PyYAML  
**Storage**: PostgreSQL 16  
**Testing**: pytest, pytest-asyncio, respx, pgserver (local Postgres, R17), time-machine, coverage.py,
pip-audit; golden eval set in `tests/eval/`  
**Target Platform**: Linux container (Docker) + managed PostgreSQL + host scheduler for jobs  
**Project Type**: Single backend service (no frontend)  
**Performance Goals**: Median reply < 5 s, p95 < 10 s (normal path < 1 s: DB lookup +
templates); pilot scale of at most a few messages per second  
**Constraints**: WhatsApp replies ≤ 480 chars; SMS replies ≤ 2 segments (306 GSM-7 / 134 UCS-2
chars); prices current if ≤ 3 days old (Asia/Karachi); no phone numbers at rest; no network in
tests  
**Scale/Scope**: 5 crops × 10 Punjab mandis at launch; pilot of ≥ 20 farmers; hundreds of
messages/day

All former unknowns are resolved in [research.md](./research.md). Two items depend on external
facts and are gated by blocking tasks rather than left unresolved: SMS vendor selection (R4) and
AMIS terms/coverage verification (R6).

**Structure Decision**: Single backend project (`src/kisan/` + `tests/`). The constitution's
required separation (channel adapter, orchestration, data connectors, LLM client) is met by
packages inside one service; the eligibility rules engine is not part of this feature. The
earlier `specs/001-todo-app/` belongs to the previous scope and is not used.
